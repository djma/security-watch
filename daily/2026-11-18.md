## Devices & accounts

Google has not reported these as exploited. **Do:** update to **158.0.8127.36** on Linux, **158.0.8127.36/.37** on Windows and Mac (Help → About Google Chrome), and **158.0.8127.42** on Android (Play Store, rolling out over the next few days). Other Chromium browsers should follow. Extended Stable was last refreshed on Nov 11 to **156.0.8078.100** and does not yet include these 158 fixes. ## Servers & dev tools

- **Java4Shell (CVE-2026-114938): critical memory corruption in OpenJDK's Base64 decoder.** On x86-64 CPUs with AVX-512 VBMI, a crafted Base64 payload can cause an out-of-bounds write in the HotSpot intrinsic (the one used by `java.util.Base64`). CISA says that can crash the JVM and allow unauthenticated remote code execution, and it asked for immediate patching. ARM64 is not affected. The bug is in the 17, 21, 25 and 27 lines (from 17.0.6 onward, when the intrinsic was added); Java 8 and 11 are not affected by this CVE but still have other fixes in the same Nov 17 release. Researchers at Calif say some widely used Java apps can be reached without a login. Oracle and CISA have not reported exploitation in the wild, and it is not on KEV. **Do:** upgrade Oracle Java SE / OpenJDK builds to **17.0.21.1**, **21.0.13.1**, **25.0.5.1** or **27.0.1.1** (or **11.0.33.1** / **8u513** for the rest of the CPU). Check vendor builds (Temurin, Corretto, and others) and anything that ships a bundled JRE, including containers. If you cannot patch yet, start the JVM with `-XX:-UseBASE64Intrinsics` or, on x86 only, `-XX:UseAVX=2`. [CISA alert](https://www.cisa.gov/news-events/alerts/2026/11/17/critical-java-vulnerability-requires-immediate-patching) · [OpenJDK advisory](https://openjdk.org/groups/vulnerability/advisories/2026-11-17) · [Oracle CPU](https://www.oracle.com/security-alerts/cspunov2026.html) · [JFrog write-up](https://research.jfrog.com/post/java4shell-vulnerability/)

- **Rust: zip, libz-sys and actix-http advisories issued Nov 17.** The `zip` crate's `ZipArchive::extract` can write outside the destination through chained or absolute symlink targets (**CVE-2026-115908**, 7.2.0–8.x). Related zip issues include a missing AES authentication check (**CVE-2026-115906**), a legacy-decoder allocation DoS when the `legacy-zip` feature is on (**CVE-2026-115907**), and `ZipStreamReader` trusting local-header names that can differ from the central directory (**CVE-2026-115905**). `libz-sys` 1.1.25–1.1.32 has a heap overflow in zlib's non-blocking `gzwrite` path (**CVE-2026-85091**). `actix-http` has HTTP/1.1 chunked-body parsing bugs that can stall decoding or desynchronise request framing. More Hickory DNSSEC issues were also published; the fix is still **0.26.2**. Not reported as exploited. **Do:** move `zip` to **9.0.5** or later (covers all four; if you extract untrusted archives with `ZipStreamReader`, also turn on `enforce_header_consistency(true)`, which is off by default). Update `libz-sys` to **1.1.33** or later, and `actix-http` to **3.21.3** or later. [RUSTSEC-2026-0546 (zip path traversal)](https://rustsec.org/advisories/RUSTSEC-2026-0546.html) · [RUSTSEC-2026-0544 (libz-sys)](https://rustsec.org/advisories/RUSTSEC-2026-0544.html) · [RUSTSEC-2026-0553 (actix-http)](https://rustsec.org/advisories/RUSTSEC-2026-0553.html) · [RustSec advisories](https://rustsec.org/advisories/)

- **Malicious npm package `signup-lib@99.99.99`.** A dependency-confusion package whose postinstall hook sends the machine's hostname to `h1.cx`. **Do:** search lockfiles for `signup-lib`. If you find it, remove it and check whether the host reached `h1.cx`. [GitHub advisory](https://github.com/advisories/GHSA-r87g-8hwq-8mxh)
