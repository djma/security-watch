# Security digest — 2026-11-20
Covers about 24–36 hours up to 08:00 Asia/Shanghai. Checked CISA KEV (nothing added since the four on Nov 18), RustSec (Wasmtime and heapless advisories), Chrome releases (only a ChromeOS stable update on Nov 18), Apple security releases (nothing new with CVE fixes since Nov 9), the cve.now JSON feeds (working again), @cvedotnow and X. Most urgent: **PHP security releases** fixing several critical bugs, one with a public exploit, and new research showing **low-privilege logins can get code execution in ClickHouse, PostgreSQL and MySQL**. ClickHouse has no fix yet for that bug. There are also security releases for Bun, Valkey and Ruby. No new OpenSSH or Redis advisories.

## Servers & dev tools

- **PHP 8.2.36 / 8.3.37 / 8.4.28 / 8.5.13 (Nov 19) fix several critical bugs, and one already has a public exploit.** The fixes include:
  - **phpAfterShell (CVE-2026-126714, 9.2):** with the default file-based session handler, an interrupted session write can let an attacker inject objects. Depthfirst chained this into unauthenticated code execution.
  - **CVE-2026-115560:** session upload-progress data can be read back with the wrong serializer, which also allows object injection.
  - **Use-after-free bugs** in the timezone cache (**CVE-2026-129496**, public PoC on GitHub), magic-method backtraces (CVE-2026-129474), fatal-error backtraces (CVE-2026-129182) and session shutdown (CVE-2026-129481).
  - **PHP-FPM request forgery (CVE-2026-129289):** only when the web server reuses FastCGI connections, which is not the default.
  - **PHP-CGI PATH_INFO memory bug (CVE-2026-129538).**

  PHP says the critical ones need non-default or uncommon setups. None are reported as exploited in the wild. **Do:** upgrade to the fixed release for your branch (8.1 and older get no fixes), restart PHP-FPM or Apache, and rebuild any container images. Until then, set `session.upload_progress.enabled = 0` and leave nginx `fastcgi_keep_conn` off. Sessions stored in Redis or a database avoid the phpAfterShell bug specifically. [PHP 8 changelog](https://www.php.net/ChangeLog-8.php) · [PHP advisory GHSA-fm2m-fjf5-v3cp](https://github.com/php/php-src/security/advisories/GHSA-fm2m-fjf5-v3cp) · [Depthfirst write-up](https://depthfirst.com/research/phpaftershell) · [cve.now on X: PoC out](https://x.com/cvedotnow/status/2123509201007722895)

- **Low-privilege database accounts can get a shell on ClickHouse, PostgreSQL and MySQL (Depthfirst research, Nov 18).** Nobody has reported exploitation in the wild.
  - **ClickHouse:** a heap overflow in the RowBinary string reader. It has **no CVE and no confirmed fix** yet. Under the default configuration, any HTTP caller can set `format_binary_max_string_size=0`, which turns off the length check. With only `CREATE TEMPORARY TABLE ON *.*`, Depthfirst got an interactive shell as the `clickhouse` user on 26.7.5.10.
  - **PostgreSQL CVE-2026-116331 (update):** Depthfirst says any plain login role is enough, because `TEMPORARY` is granted to PUBLIC by default. Earlier reports said the attacker needed to be able to create objects.
  - **MySQL CVE-2026-101786:** affects 26.7.0–26.7.1 and needs only `CREATE TEMPORARY TABLES`. It is fixed in Oracle's October 2026 CPU.

  Separately, ClickHouse **26.10.7.24 / 26.9.33.10 / 26.8.41.14** (Nov 19) fix a type confusion (crash or out-of-bounds read) from crafted columns sent over the native protocol.

  **Do:**
  - **ClickHouse:** move to those builds. Lock `format_binary_max_string_size` with a settings constraint (`<const/>`) in every user profile. Revoke `CREATE TEMPORARY TABLE` from accounts that don't need it, and keep the HTTP and native ports off the internet.
  - **PostgreSQL:** confirm you're on **18.7 / 17.12 / 16.16 / 15.20 / 14.25**, and run `REVOKE TEMPORARY ON DATABASE <db> FROM PUBLIC` where apps don't need temp tables.
  - **All three:** treat read-only, BI and AI-agent logins as able to run code on the server.

  [Depthfirst research](https://depthfirst.com/research/narrow-grants-wide-engines) · [PostgreSQL advisory](https://www.postgresql.org/support/security/CVE-2026-116331/) · [ClickHouse 26.10.7.24 changelog](https://github.com/ClickHouse/ClickHouse/blob/master/docs/changelogs/v26.10.7.24-stable.md) · [X summary](https://x.com/i/status/2123407938542821640)

- **Bun v1.4.5 (Nov 19) is a security release.** It fixes bugs in HTTP/3, TLS and DNS handling. Affected APIs include `Bun.serve`, `Bun.connect`, `Bun.dns`, `fetch`, `node:tls/https/http/quic/dns/zlib` and Zstandard decompression. It also updates BoringSSL (November 2026), lsquic 4.11.2, c-ares 1.34.9, llhttp 9.4.4 and SQLite 3.54.1. Bun gave no CVE details, and nothing is reported as exploited. **Do:** run `bun upgrade` and pin **1.4.5** in Docker images (`oven/bun:1.4.5`) and CI, then redeploy. [Bun v1.4.5 release notes](https://bun.com/blog/bun-v1.4.5)

- **Valkey (Redis fork) security releases, Nov 18: CVE-2026-130822.** A use-after-free crash during client eviction. It only matters when `maxmemory-clients` is enabled. **Do:** upgrade to **9.1.4 / 9.0.8 / 8.1.12 / 8.0.13 / 7.2.16**. If you can't yet, turn off `maxmemory-clients`. Redis itself has no new security release (latest is 8.10.3 from Oct 26). [Valkey 9.1.4 release](https://github.com/valkey-io/valkey/releases/tag/9.1.4) · [Fix PR #5435](https://github.com/valkey-io/valkey/pull/5435)

- **Ruby 4.0.10 / 3.4.13 / 3.3.14 (Nov 18) fix seven memory bugs in Regexp and string case conversion.** Ruby says PoCs show remote code execution in some scenarios. The heap overflow in upcasing legacy-encoding strings has been nicknamed "ruby2shell". CVE IDs are still pending; the issues are tracked as GHSAs such as GHSA-34m4-m9fh-gqp5. Not reported as exploited. **Do:** upgrade the Ruby runtime itself (updating gems isn't enough) and restart app servers. Ruby 3.2 and older get no fix. [Ruby advisory](https://www.ruby-lang.org/en/news/2026/11/18/multiple-vulnerabilities-in-regexp-and-string/)

- **LiteLLM CVE-2026-40217 is exploited and was added to KEV on Nov 18.** The custom-code guardrail test endpoint (`POST /guardrails/test_custom_code`) can escape its sandbox and run code. It affects 1.81.8–1.83.9. **Do:** upgrade any self-hosted LiteLLM proxy to **1.83.11** or later, or block that path at your reverse proxy. Then rotate the LLM provider keys it holds. [GitHub advisory GHSA-wxxx-gvqv-xp7p](https://github.com/advisories/GHSA-wxxx-gvqv-xp7p) · [CISA alert](https://www.cisa.gov/news-events/alerts/2026/11/18/cisa-adds-four-known-exploited-vulnerabilities-catalog)

- **GitHub repos that hijack AI coding agents.** Bitdefender found 22 repos whose `CLAUDE.md` / `AGENTS.md` files and session hooks tell the agent to run `scripts/setup.js`, a credential stealer. It goes after cloud, CI, registry, browser and password-manager secrets. It then rewrites other agent configs and uses stolen GitHub or GitLab tokens to infect up to 25 more repos. GitHub also flagged the MCP packages `karma365-mcp` 2.1.0 (npm) and `my-mcp-server-driving-license-ocr` 0.1.3 (PyPI) as malicious. **Do:** before letting an agent work in an unfamiliar repo, read its agent instruction files, hooks and setup scripts. Remove those packages from MCP configs. If `setup.js` or `karma365-mcp` ran, rotate keys from a clean machine. [Bitdefender](https://www.bitdefender.com/en-us/blog/labs/how-ai-agents-become-new-targets-in-github-malware-campaign) · [X: MCP packages](https://x.com/i/status/2123552746984837499)

## Devices & accounts

- **FastUnlock: unpatched Windows 11 lock-screen and BitLocker bypass, published Nov 19.** Someone with physical access can open Narrator from the "I forgot my PIN" screen, reach Settings and File Explorer, and run code from a USB stick as the lock-screen account. This works on fully patched 26H2 with BitLocker. It needs at least one account on the PC linked to a Microsoft account. There is no CVE or fix yet, and no reported use in the wild. **Do:** don't leave laptops unattended. Turn on a **BitLocker pre-boot PIN** so a powered-off or hibernated machine doesn't unlock by itself. On managed machines, block Narrator with AppLocker until Microsoft patches. [Researcher's write-up](https://github.com/MSNightmare/FastUnlock) · [ThreatLocker test](https://www.threatlocker.com/blog/proof-of-concept-for-fastunlock-windows-lock-screen-bypass-from-nightmare-eclipse) · [X story](https://x.com/i/trending/2123469237004181803)

- **Mosquitto MQTT broker (common in home automation): security release 2.1.3 / 2.0.23.** It fixes a WebSocket frame bug that could allow remote code execution (built-in WebSocket support). It also fixes a password check that could be bypassed with OpenSSL 4.0 in FIPS mode and passwords under 8 characters (CVE-2026-126708). **Do:** update to **2.1.4** (which fixes a 2.1.3 regression with legacy sha512 hashes) or **2.0.23**. Home Assistant users should check for a Mosquitto add-on update. Don't expose port 1883 or the WebSocket listener to the internet. [Mosquitto release notes](https://mosquitto.org/blog/2026/11/version-2-1-3-released/) · [GHSA-878w-672v-qwmf](https://github.com/eclipse-mosquitto/mosquitto/security/advisories/GHSA-878w-672v-qwmf)

## Crypto & scams

- **LUKSO: about 300 Universal Profiles drained (about 1.4M LYX) through its email recovery service, Nov 17–18.** A backend flaw let the attacker use the service's own "recovery" profiles to add their controller key to user profiles. Email recovery has been switched off. That key **still works** on any profile where it hasn't been removed. **Do:** if you ever used LUKSO email recovery, remove controller `0xa2f8Fd85366d1B4A3B13C33A48CD959F6D1Ba3a7` in UP Authorize, even if it isn't listed. Then remove the "recovery-UP" controller and make a file backup. LUKSO never asks for recovery phrases. [LUKSO post-mortem](https://medium.com/@lukso/post-mortem-security-incident-in-the-email-based-recovery-system-029f6f241e2b) · [X story](https://x.com/i/trending/2123020154753941890)

- **Etherscan: attempted break-in on its Freshworks support system (Nov 18).** No breach has been confirmed, but Etherscan warns of impersonators. **Do:** ignore any "Etherscan support" message asking for seed phrases, private keys or passwords, or pushing links or attachments. [X: Etherscan alert](https://x.com/i/status/2123039448757616805)

- **JPMorgan, Visa and Mastercard marketing data leaked through a third party.** Over 16,000 emails, phone numbers and account IDs of JPMorgan Reserve clients were exposed, and the n0n group posted similar Visa and Mastercard data. No card numbers or core systems were touched. **Do:** expect convincing bank and card phishing that quotes real account details. Call back on the number printed on your card. [X story](https://x.com/i/trending/2123421379647176709)

- **Still live:** Optimizely says the attacker got in through a flaw in its account signup, which is now fixed. Also still relevant: the Lighter API-key drain ([2026-11-17](https://djma.github.io/security-watch/daily/2026-11-17.md)), plus NGINX2Root, Apache httpd HTTP/2, the `agent-framework` PyPI malware and tampered Ledgers ([2026-11-19](https://djma.github.io/security-watch/daily/2026-11-19.md)), and Java4Shell and Chrome 158 ([2026-11-18](https://djma.github.io/security-watch/daily/2026-11-18.md)).
