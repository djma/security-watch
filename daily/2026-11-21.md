# Security digest — 2026-11-21
Covers about 24–36 hours up to 08:00 Asia/Shanghai. Checked CISA KEV (four added Nov 20, all enterprise products), RustSec, Chrome releases (only Dev-channel builds), Apple security releases (nothing new with CVE fixes since Nov 9), the cve.now JSON feeds, @cvedotnow and X. Most urgent: a **pam-mysql bug that lets anyone SSH in with any password** to accounts whose stored password is NULL, and **public exploit code for PHP's phpAfterShell bug**. Also: a study found **AI providers leaking and abusing secrets pasted into prompts**, new ClickHouse hardening builds, and a **$13M deployer-key theft that crashed Wagyu's wrapped Monero token on Hyperliquid**. ## Servers & dev tools

- **pam-mysql CVE-2026-124749: SSH login with any password, or none, for accounts whose stored password is NULL.** The PAM module ignored PAM's "no empty passwords" flag, so OpenSSH's safe default (`PermitEmptyPasswords no`) didn't protect these accounts. The researcher rates it CVSS 9.8. I found no reports of exploitation. It only matters if your PAM config uses `pam_mysql`. **Do:** run `grep -r pam_mysql /etc/pam.d`. If it shows up, update to **0.8.2-2.1+deb13u1** (Debian 13) or **0.8.2-2+deb12u1** (Debian 12), or your distro's fix. Also look for NULL passwords in the user table, and use key-only SSH (`PasswordAuthentication no`). [Debian DSA-6643-1](https://security-tracker.debian.org/tracker/DSA-6643-1) · [Debian LTS DLA-4919-1](https://security-tracker.debian.org/tracker/DLA-4919-1) · [X post](https://x.com/thecybersecguru/status/2123674937844195671)

- **PHP phpAfterShell (CVE-2026-126714): exploit code is now public.** Three PoC repos are on GitHub, and the predicted chance of exploitation (EPSS) passed 10% on Nov 20. PoCs are also out for CVE-2026-129289 (FPM) and CVE-2026-129474. It is not on KEV yet. Separately, a researcher found an attacker server logging about 31,000 exploit attempts with the earlier PHP2Shell bug (CVE-2026-109618). **Do:** if you haven't yet, move to **8.2.36 / 8.3.37 / 8.4.28 / 8.5.13** and restart PHP-FPM ([2026-11-20](https://djma.github.io/security-watch/daily/2026-11-20.md) has the mitigations). [cve.now](https://cve.now/CVE-2026-126714) · [X: PHP2Shell exploitation logs](https://x.com/DFIR_Radar/status/2123839520856498217)

- **AI services are leaking secrets from prompts (HD Moore / Dragos, Nov 19).** The team planted 2 million fake secrets (canary tokens) in prompts sent to popular AI services. They found **three compromised providers**: attackers stole about 200 AWS keys from them in late October and used them for thousands of API calls. Some resellers also logged prompts even when zero-retention or privacy flags were set. **Do:**
  - Don't paste API keys, `.env` files, or logs and configs that contain credentials into AI chats or coding agents.
  - Prefer direct model providers over resellers and aggregators.
  - Rotate any cloud, exchange or API key that has been in a prompt.

  [Dragos write-up](https://www.dragos.com/blog/ai-supply-chain-security-canary-tokens) · [HD Moore on X](https://x.com/hdmoore/status/2123451306685661416)

- **ClickHouse 26.10.8.34 / 26.9.34.16 / 26.8.42.13-lts / 26.3.67.30-lts (Nov 20).** These builds include hardening fixes:
  - a heap overflow when merging corrupted `uniqCombined`/`uniqHLL12` states
  - an out-of-bounds read from `JSON` aggregate states
  - filtered `s3`/`url` grants that could be escaped with `..` or encoded paths
  - dictionary access checks

  There are no CVEs, and nothing is reported as exploited. The changelogs **don't mention the Depthfirst RowBinary heap overflow** from yesterday. **Do:** upgrade, and keep the `format_binary_max_string_size` constraint and the revoked `CREATE TEMPORARY TABLE` grants in place. [26.10.8.34 changelog](https://github.com/ClickHouse/ClickHouse/blob/master/docs/changelogs/v26.10.8.34-stable.md) · [Releases](https://github.com/ClickHouse/ClickHouse/releases)

- **pip CVE-2026-133949: a CVE now covers October's compromised eMudhra/emSign CA certificates in pip's bundled certifi.** Anyone holding those certificates can impersonate TLS servers, including PyPI. **Do:** in every venv and image, upgrade to at least **pip 26.2.2, certifi 2026.10.19 and uv 0.13.6**, or Python **3.11.18 / 3.12.16 / 3.13.18 / 3.14.10 / 3.15.2**. Rebuild containers with the layer cache off. [Python announcement](https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576) · [cve.now](https://cve.now/CVE-2026-133949)

## Crypto & scams

- **Wagyu's wrapped Monero (XMR1) on Hyperliquid crashed over 99% after its deployer key was stolen (Nov 20).** An attacker moved 5.2M XMR1 from the deployer and sold it for about **$13.3M**, mostly into ETH. Wagyu's operator blames an attack on the host 1984.hosting that exposed a key from a deleted server, and has promised personal refunds. Some on X dispute that account. Real Monero is unaffected. **Do:**
  - Treat wrapped or IOU tokens controlled by one key as counterparty risk.
  - Don't buy the "dip" in XMR1.
  - Never leave signing keys on rented servers, including ones you have since deleted.

  [Lookonchain on X](https://x.com/lookonchain/status/2123656301561667859) · [X story](https://x.com/i/trending/2123677628305379357)

- **Tampered Ledgers (update): Ledger now confirms tampered devices in Berlin since January 2026, not just Dubai.** Two Dubai buyers lost about **$604K** (1,300 SOL and 507K USDT). The units came from authorized third-party retailers, and none from ledger.com. Ledger says its chip and OS have no flaw. **Do:** buy hardware wallets only directly from the maker. If yours came from a retailer, move funds to a new seed on a device bought direct. [Ledger investigation update](https://support.ledger.com/article/Update-on-the-Hardware-Implant-Incident-Investigation) · [Ledger on X](https://x.com/Ledger/status/2123738538407596493)

- **Still live:** NGINX2Root ([2026-11-19](https://djma.github.io/security-watch/daily/2026-11-19.md)), the unfixed ClickHouse RowBinary bug, Bun 1.4.5, the Valkey and Ruby fixes ([2026-11-20](https://djma.github.io/security-watch/daily/2026-11-20.md)), the LUKSO controller key, and Etherscan support impersonators.
