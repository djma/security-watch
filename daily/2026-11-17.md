## Devices & accounts

- **Malicious JavaScript served through Optimizely to 178 organisations (Nov 16).** Attacker code was injected into Optimizely Web "Project JavaScript" snippets and served from Optimizely's CDN on sites including Zoom, BBC, CNN, Salesforce, GitLab, IKEA, HSBC, Equifax, Air France-KLM and Ledger. Researchers also found it on a few other script providers (Kissmetrics, StorifyMe, minute-ly). The payload swaps copied wallet addresses (EVM, Bitcoin, TRON, TON, Solana, Litecoin, Bitcoin Cash, Dogecoin), skims card numbers, grabs readable cookies plus screenshots, and sends iPhones/iPads to the Coruna and DarkSword exploit kits. Crypto theft has been observed. Most injected scripts were removed by the evening (UTC), and how the attacker got in is still unknown. **Do:** if you sent crypto on Nov 16, check the destination address against the original source. Watch card statements. Keep iPhone/iPad on the latest iOS (27.2.1 / 26.7.3 / 18.7.12). Site owners using Optimizely should audit Project JavaScript and recent changes, and block `1688360[.]cc`. [StepSecurity write-up](https://www.stepsecurity.io/blog/optimjack-optimizely-hosted-scripts-crypto-clipper-card-skimmer) · [Scott Helme (Report URI) on X](https://x.com/Scott_Helme/status/2122464168989098461) · [X story](https://x.com/i/trending/2122451367126327670)

- **Firefox sandbox escape newly rated critical (CVE-2026-124855, 9.6).** Fixed on Nov 10. Not reported as exploited. **Do:** make sure Firefox is on **160** (or ESR **153.7**), and Thunderbird on 160 / 153.7. [Mozilla advisories](https://www.mozilla.org/en-US/security/advisories/) · [cve.now on X](https://x.com/cvedotnow/status/2122386115243995279)

## Servers & dev tools

- **Hijacked WPPConnect releases on npm (WhatsApp API library).** `@wppconnect-team/wppconnect@2.4.1` and `@wppconnect/server@2.10.82` send environment variables, `.env` files and WhatsApp session tokens to a Telegram bot. Later reports say some GitHub nightly assets and specific Docker image digests are affected too. **Do:** check lockfiles and images. Go back to **2.4.0 / 2.10.81** (verified builds), rotate every secret the process could read, and log out the linked WhatsApp sessions. [SafeDep on X](https://x.com/safedepio/status/2122272767248937194) · [Follow-up on X](https://x.com/Python_s_/status/2122464695336472934)

- **PostgreSQL CVE-2026-116331 now has a public PoC.** This second code-execution bug is a type confusion in the min/max aggregate optimization: a user who can create objects can run code as the database OS user. Not reported as exploited. Fixed in the Nov 12 releases. **Do:** if you haven't yet, upgrade to **18.7 / 17.12 / 16.16 / 15.20 / 14.25** (14 is now end-of-life), rebuild C extensions for CVE-2026-6460, and limit who can create objects. [PostgreSQL advisory](https://www.postgresql.org/support/security/CVE-2026-116331/) · [PT dbugs on X](https://x.com/ptdbugs/status/2122340904765657403)

- **Update on the trojanized Claude Code extension in Cursor's marketplace.** Cursor's Nov 13 report says an access key exposed by its vendor Fireworks AI let an attacker plant tampered `Anthropic.claude-code` **2.1.312 / 2.1.313** in the marketplace cache on Oct 29, for about 11 hours, reaching up to 5,000 users. The payload tried to install a persistent SSH backdoor (attacker key, SSH enabled). Uninstalling the extension alone may not remove it. **Do:** if you installed or updated Claude Code in Cursor around Oct 29, follow Cursor's notice and run its check script. Look in `~/.ssh/authorized_keys` for keys you don't recognise, and turn off SSH if you never enabled it. [Cursor incident update](https://cursor.com/blog/security-incident-update) · [Cursor security notice](https://cursor.com/blog/claude-code-extension-security-notice)

## Crypto & scams

- **Lighter: ~$15.5M drained from two market-maker accounts through a leaked API key (Nov 16).** Lighter says a leaked API key for a specific trader's account caused it and that the protocol and contracts weren't affected. It paused withdrawals, used Guardian mode to recover funds from a further withdrawal attempt, and returned about $5M USDC to one trader before reopening withdrawals. Per X reports, the attacker closed the victims' positions, created a 0%-fee public pool from the victim account, and moved the USDC through it. Reports blame nonce reuse in unofficial custom signing code and say Lighter added IP allow-lists. **Do:** if you trade by API on any venue, use the official SDKs, IP-allow-list and scope API keys (no transfer/withdraw where possible), keep keys out of logs and repos, and rotate any key that has been on a shared machine. [Lighter on X](https://x.com/Lighter_xyz/status/2122311006604984497) · [Breakdown on X](https://x.com/0xTria/status/2122280548047671629) · [X story](https://x.com/i/trending/2122278860343452058)

- **Trezor customer data leaked through shipping partner Skladon.** About 27,000 orders placed Aug 9–Nov 7 were exported: name, phone, address, email and order details. US orders weren't affected. Trezor's systems and devices weren't affected. Scam calls have already been reported. **Do:** if you ordered then, expect calls, texts, emails and even letters that quote your real order. Hang up and contact Trezor Support yourself. Never share your recovery seed with anyone. [Trezor on X](https://x.com/Trezor/status/2122363569891135655)

- **Gnosis Safe with Zodiac Roles drained of ~$6.45M (Nov 16).** Per PeckShield/X reports, the attacker abused permissions already granted through the Zodiac Roles module (about $4.3M USDC plus $1.7M syrupUSDC), swapped the funds to ETH, then sent part to Monero. **Do:** if your Safe uses Roles or other delegate modules, review which keys hold roles and how wide their scopes are. [X post](https://x.com/king_steph10051/status/2122479015563034992)

- **Still live:** fake "Coinone support" contacts after the support-chat leak, and the `@claudecode/cli` npm malware (see [2026-11-16](https://djma.github.io/security-watch/daily/2026-11-16.md)).
