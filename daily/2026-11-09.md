## Crypto & accounts

- **LNbits tells every operator to shut down their servers now (Nov 8).** After "a wave of attacks", the Lightning wallet software asked all self-hosted LNbits instances to stop immediately and paused its hosted my.lnbits.com; one operator (BitTipBot) reported about 2.29M sats withdrawn by newly created accounts over five hours. Actively exploited; patches promised within 24–48 hours. Lightning and Bitcoin themselves are not affected. **Do:** if you run LNbits, stop it now and keep it offline until the patched release ships; then review accounts/wallets created recently and move funds out of hot wallets. If you hold sats on someone else's LNbits instance (tip bots, vouchers), withdraw once they're back up. [LNbits alert](https://x.com/lnbits/status/2119428804951048237) · [X story](https://x.com/i/trending/2119471425191034893)

- **Update: Keplr / Web3Auth social-login drain.** Web3Auth's whitehat rescue has secured about $5.6M, and early data suggests roughly 20% of Google/Apple-login Keplr accounts may be exposed. Seed-phrase and hardware wallets remain unaffected. **Do:** same as yesterday — don't fund social-login Keplr wallets, and ignore "recovery" DMs. [Keplr guidance](https://x.com/keplrwallet/status/2119117067500806350) · [X story](https://x.com/i/trending/2118960935272669668)

## Servers & dev tools

- **Update: OpenSSH *sshole (CVE-2026-123158) mass scanning.** SANS ISC honeypots now see widespread scans and exploit attempts since Nov 5, on top of XLab's malware reports. Only musl/no-PAM builds (Alpine, OpenWrt, some containers) are affected. **Do:** upgrade to **OpenSSH 10.6p2** (Alpine: `apk upgrade -U -a`) and restart sshd, or set `PasswordAuthentication no`; check for unexpected password logins on key-only accounts. [SANS ISC](https://x.com/sans_isc/status/2119456283590037577) · [OpenSSH 10.6p2](https://www.openssh.com/txt/release-10.6p2)

- **rustls 0.23.44–0.23.45 can leak early application data when Encrypted Client Hello is rejected (CVE-2026-123612, CVSS 4.6).** Data written before the handshake finishes goes to the outer public_name server. Only matters if you use ECH on the client side; no known exploitation. **Do:** bump `rustls` to **0.23.46** or later (which also fixes three October advisories); `cargo update -p rustls`. [cve.now](https://cve.now/CVE-2026-123612) · [rustls advisories](https://github.com/rustls/rustls/security/advisories)

- **Hickory DNS (hickory-proto) CPU-exhaustion via name compression (CVE-2026-123608, CVSS 8.7).** Crafted DNS messages with many records trigger quadratic work when encoding; affects 0.3.1 through 0.26.0, pulled in by many Rust resolvers and DNS servers. No known exploitation. **Do:** update `hickory-proto`/`hickory-resolver` to **0.26.2** or later (0.26.1 fixes this one; 0.26.2 fixes several other panics). Check with `cargo tree -i hickory-proto`. [cve.now](https://cve.now/CVE-2026-123608) · [Hickory advisories](https://github.com/hickory-dns/hickory-dns/security/advisories)

- **Contact Form 7 unauthenticated file upload → RCE (CVE-2026-114432, CVSS 9.8).** Versions 6.2–6.2.3 of the hugely popular WordPress plugin let anyone upload files that can run as code on common Apache setups. No exploitation yet, but CISA rates it automatable. **Do:** update to **6.2.4**. [cve.now](https://cve.now/CVE-2026-114432) · [cve.now on X](https://x.com/cvedotnow/status/2119511670150025424)

- **imgproxy heap overflow in the ICO loader (CVE-2026-123614).** A crafted ICO image can crash it or run code. **Do:** if you self-host imgproxy, update to **4.0.16**. [cve.now on X](https://x.com/cvedotnow/status/2119251454091292799)
