## Servers & dev tools

- **Update: OpenSSH *sshole is being exploited in the wild (CVE-2026-123158).** Previdian saw the first attempt under nine hours after disclosure and confirmed **root on an Alpine honeypot**; eight attempts from one Japan-geolocated IP used oversized passwords, then ran `id`/`uname`/`hostname` over non-interactive SSH. Still not on CISA KEV. Fixed in **OpenSSH 10.6p2**; Alpine shipped patched packages across supported branches. **Do:** on Alpine / musl+no-PAM hosts, `apk upgrade -U -a` (or install 10.6p2) and **restart sshd**; if you cannot patch yet, set `PasswordAuthentication no` and restart; hunt `Accepted password for` on accounts that should be key-only. [Help Net Security](https://www.helpnetsecurity.com/2026/11/06/openssh-sshole-cve-2026-123158-exploitation/) · [The Hacker News](https://thehackernews.com/2026/11/hackers-exploited-openssh-sshole-flaw.html) · [OpenSSH 10.6p2](https://www.openssh.com/txt/release-10.6p2)

- **Babelfish for PostgreSQL unauthenticated RCE via TDS prelogin (CVE-2026-119923, CVSS 9.8).** A heap overflow in the SQL Server–compatibility TDS handshake lets a remote attacker who can reach the TDS port (default **1433**) run OS commands as the database process user — no login needed. Affects Babelfish extension lines **1.0–1.5, 2.1–2.15, 3.1–3.12, 4.0–4.8, 5.1–5.4** and Aurora PostgreSQL clusters with Babelfish enabled. Vanilla PostgreSQL without Babelfish is not in scope. No known exploitation / not on KEV. **Do:** upgrade Babelfish to **4.10 / 5.6 / 6.1+**, or Aurora to the matching patched engine builds (e.g. **1.5.5, 1.17.2, 2.3.5, … 6.1.0** — see AWS bulletin); until then block or tightly firewall port 1433. [cve.now](https://cve.now/CVE-2026-119923) · [AWS bulletins index](https://aws.amazon.com/security/security-bulletins/) (2026-166-AWS)

- **Rust: actix-web / actix-http request-smuggling + compression DoS.** Fresh RustSec set issued Nov 6: HTTP/1 chunked trailer smuggling (**RUSTSEC-2026-0446**), compressed-body memory exhaustion before extractor limits (**RUSTSEC-2026-0447 / 0448**), and large-window Brotli allocating ~1 GiB from an ~850-byte request (**RUSTSEC-2026-0455**; Brotli on by default in Actix Web). No known exploitation. **Do:** bump `actix-http` to **≥3.20.3** and `actix-web` to **≥4.18.2**; until then reject `Content-Encoding: br` (and other compressed bodies) at the reverse proxy. [RUSTSEC-2026-0446](https://rustsec.org/advisories/RUSTSEC-2026-0446) · [RUSTSEC-2026-0447](https://rustsec.org/advisories/RUSTSEC-2026-0447) · [RUSTSEC-2026-0455](https://rustsec.org/advisories/RUSTSEC-2026-0455)

- **Rust: SurrealDB / surrealkv memory-safety trio.** `surrealkv` OOB-reads short internal keys (**RUSTSEC-2026-0452**, fixed **≥1.2.0**); SurrealDB KV backends UAF if an `affinitypool::spawn_local` future is leaked (**RUSTSEC-2026-0453**, fixed in `surrealdb` **≥3.3.0**); `surrealdb-core` data-race / double-free via unsound `Send`/`Sync` in `reblessive` (**RUSTSEC-2026-0454**, fixed **≥4.0.0**). Local/memory-corruption class; no known remote exploitation. **Do:** if you run or depend on SurrealDB, upgrade to those builds and run `cargo audit`. [RUSTSEC-2026-0452](https://rustsec.org/advisories/RUSTSEC-2026-0452) · [RUSTSEC-2026-0453](https://rustsec.org/advisories/RUSTSEC-2026-0453) · [RUSTSEC-2026-0454](https://rustsec.org/advisories/RUSTSEC-2026-0454)

- **Self-hosted 2FAuth reverse-proxy guard can mint admins (CVE-2026-63438).** With `AUTHENTICATION_GUARD=reverse-proxy-guard`, an unauthenticated client who can reach the app and forge auth headers can skip login and take over (including admin). Fixed in **8.0.0**. **Do:** upgrade to **v8.0.0+** and set `TRUSTED_PROXIES` to your real auth proxy; if you cannot patch yet, turn the reverse-proxy guard off. [GitHub advisory](https://github.com/Bubka/2FAuth/security/advisories/GHSA-r9xx-45m8-mw24) · [2FAuth v8.0.0](https://github.com/Bubka/2FAuth/releases/tag/v8.0.0)

- **Playwright still ships pre-patch Chromium with the sandbox off by default.** Playwright **1.64.1** bundles Chromium from before Chrome’s late-October Critical fixes, and launches with `chromiumSandbox: false` unless you override it — relevant if AI agents / CI fetch untrusted pages. **Do:** prefer `chromium.launch({ channel: 'chrome', chromiumSandbox: true })` against a current system Chrome, or pin a newer Playwright once it rebases Chromium; in Docker run non-root with Playwright’s seccomp profile. [advisory write-up](https://pranava0x0.github.io/vibe-coding-security/advisories/2026-11-playwright-chromium-patch-gap.html)

## Devices & accounts

- **Windows Paint RCE fix is finally in the Microsoft Store (CVE-2026-83844, CVSS 8.1).** Out-of-bounds read that Microsoft rates as network RCE without sign-in; high attack complexity, no known exploitation. Paint is a Store app, so **Windows Update does not deliver the fix**. Fixed build is **11.2609.401.0** (the older “11.2605.91.0” cutoff in the CVE record never shipped). **Do:** open Microsoft Store → Library → Get updates, confirm Paint ≥ 11.2609.401.0 for every user profile (and the provisioned copy); Store auto-update also works when enabled. [The Hacker News](https://thehackernews.com/2026/11/microsoft-paint-rce-fix-now-available.html) · [MSRC](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-83844)

- **Claude Code was putting account emails into User-Agent headers on web fetches.** Model-chosen `curl`/shell requests included the signed-in address (e.g. to Wikipedia), which then showed up in site logs and spam. Anthropic shipped a default-on privacy guard in **2.1.317+** that blocks Bash/PowerShell/Monitor calls carrying the email + User-Agent; it does **not** cover every path (scripts, WebFetch/WebSearch, MCP). Permanent fix is removing the email from model context. **Do:** update Claude Code to **≥2.1.317**, leave the privacy mod on, and treat unexpected email-targeted phishing as plausible if you used older builds. [GitHub issue #107757](https://github.com/anthropics/claude-code/issues/107757) · [privacy mod README](https://raw.githubusercontent.com/anthropics/claude-code/main/mods/privacy/README.md)

## Crypto & accounts

- **Gnosis Pay disclosed a legacy branded-card data breach (detected Nov 3, posted Nov 6).** Unauthorized access to the B2C card system exposed customer info (notifications cite names, home addresses, wallet addresses, and in some cases full card number / expiry / CVV). Funds and the enterprise white-label platform were not affected; cards cancelled; 3D Secure now mandatory until the B2C system retires Dec 20. **Do:** if you got the email, assume phishing that uses your real details; never share seed/PIN/card number out-of-band; open only the official web app you type yourself. [Gnosis Pay blog](https://gnosispay.com/blog/data-breach-legacy-system-gnosis-pay-branded-cards)

- **South Korea’s GOPAX paused deposits/withdrawals/trading after a hacking-threat email (Nov 6).** Yonhap and local outlets report an unverified email claiming a breach; GOPAX moved assets toward cold storage and left only manual support withdrawals. No confirmed fund loss disclosed yet. **Do:** if you hold funds there, use only official support channels for manual withdrawal, ignore “resume trading” phishing, and treat any unexpected login/password-reset mail as hostile until the exchange posts an all-clear. [Yonhap](https://en.yna.co.kr/view/AEN20261106011751320)

## Scams

- **Address-poisoning / dust campaigns keep draining wallets (TRON + Solana).** One widely shared case: a trader lost **~$535k USDT** after a 1 USDT lookalike dust tx, then copied the poisoned address from history for the real send. Separately, Phantom users report the app locking sends/swaps after malicious dust hits its compliance filter (on-chain funds still move if you export the seed elsewhere). **Do:** never copy a receive address from recent-tx history after a surprise tiny deposit; paste from a saved contact / fresh source and check every character; if Phantom locks you, export the recovery phrase to another wallet rather than “support” DMs. [X story — address poisoning](https://x.com/i/trending/2118424040620593422) · [X story — Phantom dust locks](https://x.com/i/trending/2118833478636638625)
