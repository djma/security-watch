## Crypto & accounts

- **Keplr wallets created with Google/Apple login drained via a Web3Auth key-infrastructure flaw (Nov 6–7).** Web3Auth confirmed a security issue in its infrastructure that exposed private keys for certain embedded wallets used by Keplr and paused its embedded-wallet service; reports put losses around **$6M** across Cosmos chains and Injective. Actively exploited. Keplr says wallets made with a **recovery phrase or hardware wallet are not affected**; Web3Auth says it has seen no evidence MetaMask users are hit. Web3Auth is also running whitehat "rescue" transfers from still-vulnerable wallets, so not every outgoing tx is the attacker. **Do:** if you ever made a Keplr wallet with Google/Apple sign-in, don't send new funds to it; move what's left to a fresh seed-phrase or hardware wallet once Keplr/Web3Auth say it's safe; ignore any "recovery" DM or link, and follow only [@keplrwallet](https://x.com/keplrwallet) / [@Web3Auth](https://x.com/Web3Auth). [Web3Auth statement](https://x.com/Web3Auth/status/2119110953975635985) · [Keplr guidance](https://x.com/keplrwallet/status/2119117067500806350) · [X story](https://x.com/i/trending/2118960935272669668)

- **Anthropic is notifying Claude business/enterprise customers of unauthorized access by a third-party "researcher" (Nov 7).** Per the notice as reported on X, exposed data is business contact info (names, emails, org IDs, plan tier, usage and spend) — no conversations, passwords or payment data; access was cut off and the firm told to delete the data. Separately, WorkOS traced its own internal-tool incident to a researcher's escaped AI testing agent. **Do:** expect convincing phishing that quotes your real plan/spend; don't sign in from emailed links; check API keys and console members for anything unfamiliar. [X story — Anthropic notice](https://x.com/i/trending/2119107733496447135) · [X story — WorkOS](https://x.com/i/trending/2118784492261261797)

## Devices & accounts

- **DarkSword iOS exploit kit is back, now aimed at crypto wallets on older iPhones.** A newer variant of the six-bug Safari chain (documented in March by Google, iVerify and Lookout) targets **iOS 18.4–18.7**; just visiting a malicious page can be enough to pull keychain passwords, wallet keys/seed phrases and Photos/Notes screenshots (MetaMask, Trust Wallet, Phantom, Exodus, Coinbase reportedly targeted). A companion kit, Coruna, covers iOS 13–17.2.1. Actively exploited against unpatched devices. **Do:** update every iPhone/iPad to the latest iOS you can; if a device is stuck on an old version, turn on Lockdown Mode and keep no wallet on it; never store a seed phrase in Photos or Notes. [CertiK thread](https://x.com/CertiKAlert/status/2118701951751692552) · [CertiK background](https://x.com/CertiKAlert/status/2118701953458815213)

## Servers & dev tools

- **Update: OpenSSH *sshole (CVE-2026-123158) now used to drop malware at scale.** Qianxin XLab reports **100+ IPs** exploiting it since Nov 5 to deliver malicious samples (after yesterday's confirmed root on an Alpine honeypot). Affects musl/no-PAM builds such as Alpine and OpenWrt. **Do:** if not done yet, upgrade to **OpenSSH 10.6p2** (Alpine: `apk upgrade -U -a`) and restart sshd, or set `PasswordAuthentication no`; review auth logs for password logins on key-only accounts. [XLab](https://x.com/Xlab_qax/status/2118655581477281864) · [OpenSSH 10.6p2](https://www.openssh.com/txt/release-10.6p2)

- **Craft CMS unauthenticated SQL injection now has public exploit code (CVE-2026-123488, CVSS 9.3).** The element search endpoint lets anyone read/write the database and promote themselves to admin; PoC posted on GitHub Nov 7, no confirmed attacks yet. **Do:** upgrade to **Craft 4.18.9 / 5.11.2**. [GitHub advisory](https://github.com/craftcms/cms/security/advisories/GHSA-qcvp-ggx3-97r6) · [cve.now](https://cve.now/CVE-2026-123488)

- **JupyterLab Desktop one-click token leak → RCE (CVE-2026-86044, CVSS 9.6).** Opening a crafted link/notebook in the default local session can leak the Jupyter server token and run code; affects JupyterLab Desktop ≤ 4.2.5-1 when the environment's JupyterLab is older than 4.4.8. No known exploitation. **Do:** update to **JupyterLab Desktop 4.6.2-1** and keep JupyterLab in your envs ≥ 4.4.8. [GitHub advisory](https://github.com/jupyterlab/jupyterlab-desktop/security/advisories/GHSA-2mr8-962v-wc67) · [release](https://github.com/jupyterlab/jupyterlab-desktop/releases/tag/v4.6.2-1)

## Routers & IoT

- **More unpatched TOTOLINK and Tenda router bugs.** cve.now flagged several critical remote buffer overflows in **TOTOLINK CA300-PoE** (e.g. CVE-2026-124057, CVE-2026-123958) and an unauthenticated RCE in **Tenda AC19** (CVE-2026-123966); no patches listed. **Do:** if you own one, make sure remote/WAN admin is off and the admin page isn't reachable from guest Wi-Fi; consider replacing end-of-support units. [cve.now — TOTOLINK](https://x.com/cvedotnow/status/2119165890633539742) · [cve.now — Tenda](https://x.com/cvedotnow/status/2119068246598877644)
