# Security digest — 2026-11-19
Covers about 24–36 hours up to 08:00 Asia/Shanghai. Checked CISA KEV (four additions on Nov 18, one of them Synology NAS), nginx.org advisories, RustSec, Chrome releases (only early-stable 159 builds, no new security notes), Apple security releases (latest still Nov 9 / tvOS Nov 13), @cvedotnow and X. The cve.now JSON feeds returned errors again. Most urgent: **NGINX2Root**, five critical nginx bugs with a public proof of concept, and Apache httpd's HTTP/2 bug, which is now reported as exploited. No new Redis, ClickHouse server, PostgreSQL, OpenSSH or Bun advisories.

## Servers & dev tools

- **NGINX2Root (CVE-2026-123007 and four related bugs): unauthenticated code execution in nginx, fixed Nov 18.** The main bug is memory corruption in HTTP/2 flow control, present since 1.9.5 (2015). Related fixes cover a use-after-free in HTTP/2 (CVE-2026-123633), HTTP/3 (CVE-2026-121810), the resolver (CVE-2026-123634) and the mail proxy (CVE-2026-113425). F5 scores all five 9.2 and says code execution needs ASLR to be off or bypassed; Wiz and Xint say they bypassed it in tests. A public PoC exists, though it is limited. No exploitation in the wild has been reported, and it is not on KEV. **Do:** upgrade to **nginx 1.31.9** (mainline) or **1.30.7** (stable); NGINX Plus is fixed in **37.3.0.1 / 37.0.8.1**. Fully restart nginx or do a binary upgrade, because a reload leaves the old binary running. Official Docker images already have the fixed tags. Debian and Ubuntu packages were not fixed as of Nov 18, so check your distro's advisory. Until you can upgrade, `http2 off;` (and turning off HTTP/3) blocks the two HTTP/2 bugs. Check exposure with `openssl s_client -alpn h2` against the origin. Per X reports, Kubernetes ingress-nginx did not yet have a fix. [nginx security advisories](https://nginx.org/en/security_advisories.html) · [The Hacker News](https://thehackernews.com/2026/11/10-year-old-nginx-http2-flaw-lets.html) · [X corroboration](https://x.com/TheHackersNews/status/2123122388644856164)

- **Update: Apache httpd CVE-2026-119618 (mod_http2 race, RCE) is now reported as exploited.** Singapore's CSA warned of reported exploitation. It is not on KEV yet. Affected: 2.4.55–2.4.70 with HTTP/2 on. **Do:** make sure you are on **httpd 2.4.71** or later (or a distro build that includes the fix). If you cannot upgrade, turn off HTTP/2 (`Protocols http/1.1`). [Apache httpd 2.4 vulnerabilities](https://httpd.apache.org/security/vulnerabilities_24.html) · [X: CSA warning](https://x.com/DualLtd/status/2122859838174642612)

- **Microsoft's `agent-framework` PyPI package was hijacked: versions 1.26.1 and 1.26.2 steal credentials.** They were uploaded on Nov 17 (20:35 and 21:08 UTC) and use a `.pth` startup hook. It runs on every Python start, even if you never import the package, and harvests Azure, GitHub Actions, npm, git and other CI/CD secrets. PyPI has removed them. **Do:** search lockfiles, CI caches and container images for `agent-framework==1.26.1/1.26.2` and pin **1.26.0**. If you find either version, rebuild the environment and rotate every cloud, GitHub, npm and CI token that machine or job could see. [GitHub advisory GHSA-764m-3ppc-5m73](https://github.com/advisories/GHSA-764m-3ppc-5m73) · [Socket on X](https://x.com/SocketSecurity/status/2122832360366325864)

- **AdminNeo (the single-file Adminer fork) has seven CVEs, including no-password login through its ClickHouse driver.** CVE-2026-130366 (ClickHouse driver) and CVE-2026-130380 (MS SQL driver) are 9.2 authentication bypasses with public exploits, and the TOTP plugin can be skipped. **Do:** upgrade to **AdminNeo 5.9.1**. Better still, take database admin panels off the internet (VPN or SSH tunnel), and rotate any database credentials used through an exposed instance. [cve.now on X](https://x.com/cvedotnow/status/2122863206666223989) · [AdminNeo](https://github.com/adminneo-org/adminneo)

- **Rust `lettre` (SMTP email crate): six advisories on Nov 18.** They include SMTP command injection through missing dot-stuffing after bare LF/CR (RUSTSEC-2026-0561), STARTTLS response injection by a man in the middle (RUSTSEC-2026-0560), and mail for quoted local-part addresses going to a different address (RUSTSEC-2026-0563). The rest are denial-of-service bugs. Not reported as exploited. **Do:** `cargo update -p lettre` to **0.11.24** or later. [RUSTSEC-2026-0561](https://rustsec.org/advisories/RUSTSEC-2026-0561.html) · [RustSec advisories](https://rustsec.org/advisories/)

## Devices & accounts

- **Synology NAS: CISA added DSM CVE-2024-10441 (a Pwn2Own 2024 RCE, CVSS 9.8) to KEV on Nov 18, so it is now exploited.** It allows unauthenticated remote code execution through the system plugin daemon, and BeeStation is affected too. **Do:** in DSM Control Panel → Update & Restore, make sure you are on at least **7.2.2-72806-1** (or **7.2.1-69057-6**, **7.2-64570-4**, **7.1.1-42962-7**). BeeStation needs **BSM 1.1-65374** or later. Don't expose DSM's admin port to the internet. [Synology-SA-24:20](https://www.synology.com/en-global/security/advisory/Synology_SA_24_20) · [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)

- **Philips Hue Bridge: a critical heap-overflow RCE (CVE-2026-126978) was published.** It was reported on X alongside a separate Hue Bridge Pro SQL-injection RCE that needs network access and a login. We couldn't confirm the fixed firmware version. **Do:** check the Hue app for a pending Bridge software update, install it, and keep automatic updates on. [X report](https://x.com/dailycve/status/2123139437354008831)

## Crypto & scams

- **Tampered Ledger wallets reportedly sold at a Dubai retailer, about $604K lost.** Two buyers say a Ledger Stax and a Ledger Flex bought new at Virgin Megastore Dubai were drained (about 507K USDT and about 1,300 SOL). An implant was reportedly confirmed in the Flex. Ledger has not confirmed this. **Do:** buy hardware wallets direct from the maker. Only use a recovery phrase the device generates itself, never a pre-printed or pre-filled one. Reject opened or "returned" boxes, and run the vendor's genuine-device check. [X report](https://x.com/whalebaywatch/status/2122948397774811646)
